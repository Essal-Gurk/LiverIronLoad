# Security and privacy

Version 0.8 is experimental. There is no guaranteed support period or incident
response time. Images are processed locally; user-invoked documentation links
open external websites. The plugin does not upload DICOM images.

For a non-sensitive defect, open an issue with the plugin/IsiX/macOS versions,
reproduction steps and a synthetic example. Never post patient data or secrets.
For a vulnerability containing sensitive details, use GitHub private vulnerability
reporting when the repository owner has enabled it. If unavailable, first ask
for a private contact without disclosing the exploit or affected data publicly.

Maintainers should enable private vulnerability reporting before public release.
Check all exports, logs and issue attachments for identifiers. Git ignore rules
are a convenience, not a de-identification mechanism.
